# Instant navigation rig: HomeBooks

- BUILD: `EXPOSE_TESTING_API=1 npm run build`, followed by `next start` through `scripts/dev-local.mjs --production --port 3103`.
- EXPOSE: `experimental.exposeTestingApiInProductionBuild` is enabled only when `EXPOSE_TESTING_API=1` and `VERCEL_ENV` is not `production`. Real production builds never expose it.
- RUN: `npm run test:instant` builds and runs `playwright.instant.config.ts` against `PLAYWRIGHT_BASE_URL`, defaulting to `http://127.0.0.1:3103`. Playwright arguments can be forwarded after `--` for a focused route loop.
- TEST USER: local seeded `dev@finapp.local` workspace identity through `FINAPP_AUTH_MODE=dev`; no browser login navigation or storage state is required. The user is an owner with the seeded household workspace and whatever local fixture/import data is present.
- DRIFT: hosted Supabase identity and MFA versus seeded dev identity; owner/member role; workspace currency and name; review queue size; saved import/investment history; recurring/manual rows; report month; local fixture data; desktop/mobile viewport. Shell markers are static headings or frames that exist for empty and populated workspaces.
- LOOP: local build → start production server with local Supabase → run locked desktop/mobile Playwright checks → inspect failure → update one route → repeat. The loop is agent-drivable when Docker/Supabase and Chrome are available. Stop any prior process on port 3103; Playwright fails on `EADDRINUSE` because server reuse is disabled.
- LIVENESS: not applicable to the local build-and-start rig; each run builds immediately before Playwright starts the server. Remote `PLAYWRIGHT_BASE_URL` callers must independently prove the target artifact matches the branch SHA.
- WALLS: requires Node 22, Docker-backed local Supabase on ports 54321–54327, and Chrome locally. The server launcher reuses a reachable local database and strips Playwright terminal-color variables before invoking the bundled Supabase CLI, which otherwise exits in its Bun runtime. The existing development E2E config remains separate. The production build must be created by `npm run test:instant`; a normal `npm run build` does not contain the testing API and cannot produce a trustworthy `instant()` result.
